# スケジューリングアプリ

`schedule.jsx` は React と `lucide-react` を利用するアプリです。既存の React 実行環境に読み込んで使用します。

## 進捗ページ

ボードの「進捗ページに表示」をチェックしたタスクを、未着手・着手中ボードで管理します。未着手の＋からの追加も、カレンダーや一覧と共有されます。着手時の設定でやるべきことを追加できます。チェックを外してもタスクと履歴は残ります。

### カードとトークの範囲

- タスクカードをクリックすると、タスク全体のトークを表示します。未着手・完了済みのタスクも選択できます。
- やるべきことカードをクリックすると、そのやるべきことと、所属するすべての小さいタスクのトークを表示します。やるべきこと自身の外側の束ねは外し、配下の小さいタスクをそれぞれ束ねて表示します。
- 小さいタスクカードをクリックすると、その項目だけのトークを通常の時系列で表示します。自分自身のトークを束ねる外枠は表示しません。小さいタスクは常時表示し、展開・折りたたみは行いません。クリック・ダブルクリック・Enterによる引用返信は行いません。
- 自分自身だけのトークでは、そのやるべきこと・小さいタスクの作成コメントを省略します。上位の画面では、従来どおり作成見出しでまとめます。前提メモは各階層のトークの先頭に表示します。
- 上位画面で展開したコメントの本文をクリックすると、そのコメントのやるべきこと・小さいタスクを送信先として選択します。選択枠と入力欄の「送信先」で確認でき、連続送信でも選択を維持します。「表示中の範囲に戻す」で解除できます。返信・編集・リンクなどの操作では選択先を変えません。
- 引用返信はトーク内の「返信」ボタンで開始します。相手待ちは独立したカードを作らず、対象の小さいタスク・やるべきことを緑色にします。内容はその範囲のトークに残します。
- ボードのカードで表示範囲と通常のコメントの送信先を選びます。トーク内の範囲絞り込み・関連するやるべきことの選択欄はありません。大タスクのカードを選ぶと全体に戻ります。
- トークのタイトルは表示中の大タスク・やるべきこと・小さいタスクの名前です。期日やステータスは重ねて表示しません。検索と小さいタスクの完了・取り消しは「進捗リストボード」の横にあります。
- コメントの分類ラベルはIDから現在のやるべきこと名を参照します。名前の変更は過去のコメントの分類・検索・レポートにも反映します。削除済み項目は保存された名称を使います。本文・投稿日時・引用時のスナップショットは保持します。
- 送信欄の「やるべきことの追加・小さいタスクの追加・相手待ち・結論・ただのコメント」は同じ行にまとめ、幅が足りなければ折り返します。期限入力は「やるべきことの追加」を選んだ時だけ表示します。色の凡例は「色の説明」から確認できます。

やるべきことカードは、タイトル部分またはカードをドラッグして同じ大タスク内で並べ替えられます。挿入位置を太い黒線で示し、小さいタスク・完了状態・関連付けを保ったまま順番を保存します。別の大タスクへの移動は行いません。

小さいタスクも同じやるべきこと内でドラッグして並べ替え・保存できます。別の親には移動しません。カードとトークには細い濃いグレーの境界線を使い、区切り線と影は淡く表示します。状態は背景色で表します。

### 色と完了

| カード・作成見出しの状態 | 色 |
| --- | --- |
| 完了・クローズ | 青 |
| 期限超過 | 赤 |
| 相手待ち | 緑 |
| 関連するタスクの完了待ち | 黄色 |
| 進行可能・進捗中 | 紫 |
| ただのコメント | グレー |

カードは完了、関連するタスクの完了待ち、期限超過、相手待ち、進行可能の順に判定します。通常の進捗本文は青で表示します。期限超過の赤はカード・作成記録に適用し、通常の進捗や引用を期限だけで赤にしません。相手待ちコメントは緑、関連タスク待ちの進捗は黄色、ただのコメントはグレーを保ちます。特に小さいタスク自身の画面では、未完了の進捗も青です。進捗本文の青は記録の表示色で、完了状態はカード・作成見出し・チェック欄で確認できます。紫は未完了カードや、上位画面にある作成見出しに使います。完了した小さいタスクの進捗トークと引用枠はすべて青色になります。やるべきことを完了すると、その範囲の進捗トークが青色になり、案件をクローズすると案件全体の進捗トークが青色になります。「ただのコメント」は状態を変えず、完了後もグレーです。表示色を変更しても、過去のコメントの投稿日時や当時の状態は書き換えません。

小さいタスクを完了すると、カードを青色で残します。タスク全体ではやるべきことを束ね、その中で小さいタスクを束ねます。やるべきこと自身の画面では、配下の小さいタスクだけを束ねます。どちらも未完了・完了済みを問わずまとめ、「履歴を展開」で途中のトークを確認できます。青い小さいタスクカードをクリックした場合は、その小さいタスクだけの通常の時系列トークを表示します。元の追加メッセージや途中のトークは削除しません。過去のバージョンで追加メッセージが削除されている場合は、保存済みの引用やタスク名から見出しを補います。

トークの送信・編集欄に「完了」チェックはありません。小さいタスク自身のトーク画面にある「小さいタスクを完了」で完了し、「完了を取り消す」で再開します。本文の入力は不要です。完了・取り消しではトークへ自動コメントを投稿せず、完了状態と日時を直接保存します。相手待ち・関連タスク待ちの間は完了ボタンを無効にします。取り消すとカードを通常は紫に戻し、必要なら完了済みの親・案件も再開して依存関係を再判定します。本文や結論の編集だけでは完了状態を変更しません。過去のバージョンの完了コメントやボタンによる完了記録を削除した場合、または「ただのコメント」へ変更した場合も、元の完了フラグと完了日時を解除します。通常の進捗や結論コメントの削除は、完了状態を変えません。

### 結論の指定

送信・編集欄の「結論」、または保存済みコメントの「結論」チェックで指定します。完了とは独立しており、未完了・完了済みのどちらでも使えます。小さいタスク・やるべきことの上位画面では、チェックしたコメントを履歴順に改行してまとめ、折りたたんでいても表示します。画像やハイパーリンクも保持します。

やるべきことの結論はそのやるべきことへのコメント、小さいタスクの結論はその小さいタスクへのコメントを対象にします。配下の結論を親の結論に自動転記はしません。チェック解除・本文の編集・削除はすぐまとめ表示にも反映し、完了を取り消しても明示的な結論の指定は残します。結論がない場合、結論欄や未記録の案内は表示しません。従来の完了コメントも自動で結論とみなさず、必要なものだけ後からチェックできます。結論の指定は再読み込み・JSONバックアップにも保持します。

### 前提メモ

送信欄の「前提メモ」をチェックすると、目的・背景・仮定を通常コメントと別の種類で保存します。表示はグレーで「前提メモ」と明記し、タスクの相手待ち・完了状態は変えません。「ただのコメント」とは切り替え式で、既存コメントも編集から変更できます。引用・再読み込み・バックアップにも種別を保持します。

Word・テキストのレポートでは前提メモを背景情報として明記し、進捗・成果の件数には含めません。対象期間より前の前提メモと日時未記録の前提メモも、実績と分けた背景欄に記載します。未来の日付のメモは出力しません。前提として記した仮定を、検証済みの事実として推測しないよう週報作成指示にも記載します。画像・リンクも引き継ぎます。

やるべきこと自身の相手待ちが解除され、未完了の小さいタスクや、完了を待つ関連先が残っていない場合、カードに「やるべきことを完了」ボタンを表示します。押すとそのやるべきことを完了し、完了日時を保存します。トークへ自動コメントは投稿しません。小さいタスクが0件でも相手待ちが残っていれば、完了ボタンを表示しません。返信による待ちの解除や、編集中に「相手待ち」を明示的に外す操作は可能です。小さいタスクの完了だけで、やるべきことや案件全体を自動完了にはしません。

### 配下の作業と上位の色

カードと上位トークの作成見出しは、同じ判定で「今、進められる作業があるか」を表します。完了した配下は判定から外します。

- 未完了の配下に1件でも進行可能な作業があれば紫。緑と紫が混在していても、全体として作業を進められるため紫です。
- 全員が待ち状態で、相手待ちを含む場合は緑。完了済みの青と相手待ちの緑だけの場合も、動ける作業がないので緑です。
- 待っているのが関連タスクの完了だけなら黄色です。
- その項目自身に相手待ちがあっても、配下で進められる作業があれば全体は紫です。配下の作業がなくなったり、すべて完了した後も自身の相手待ちが残れば緑になります。
- 項目自体の依存先が未完了なら黄色、項目自体が期限超過なら赤、明示的に完了した項目は青という判定も維持します。期限超過の赤と作業可能かどうかは分けて判定し、期限を過ぎた相手待ちを「動ける作業」とは数えません。

配下をすべて完了しても、上位を自動完了にはしません。上位は完了操作を行える紫になり、明示的に完了すると青になります。色の集約のために、保存されている親の相手待ちフラグを書き換えることはありません。

### 相手待ちステータス一覧

タスク・やるべきこと・小さいタスクのカードにある「相手待ち一覧」ボタンで、現在相手待ちの項目と、各項目の直近の相手待ちトークをポップアップで確認できます。ボタンの件数は相手待ちの項目数です。タスクカードは案件全体、やるべきことカードはその配下の小さいタスクを含む範囲、小さいタスクカードはその項目だけを表示します。

完了済み・相手待ち解除済みの項目は含めません。トークがない相手待ちは「内容はまだ記録されていません」と表示します。画像・リンクも確認でき、ポップアップを開閉してもトークの選択範囲や保存データは変わりません。

相手待ちに返信すると、元のメッセージは返信済みになります。画面上部の「返信済みの相手待ち」で「青色で残す」（初期設定）か「非表示」を選べます。この設定は画面全体に適用し、同じブラウザーで保存します。非表示でも保存データ・引用・バックアップは保持し、いつでも再表示できます。新しい返信が相手待ちなら、その返信は緑色で表示します。

### 過去データの復元

読み込み・バックアップのインポート時に、過去のバージョンで消えた小さいタスクのカードを、残存トーク・引用に記録されたIDと親の情報から復元します。完了済みなら青色で着手中ボードに残し、未完了・相手待ちも現在の状態に応じた色で表示します。引用に残っている相手待ちメッセージと小さいタスクの追加メッセージも復元します。返信済みの相手待ちは「非表示／青色で残す」の設定に従います。明示的に手動削除した項目は復元対象から外します。完了コメントを取り消し・削除したのに完了フラグだけが残っていた過去データも、コメントによる完了が記録されている項目を対象に、読み込み時に整合させます。

過去のやるべきことに追加トークが残っていない場合は、保存されている期限・タイトルから「期限までに【タイトル】」の見出しを補って表示します。配下のトークを束ね、見出しは未完了が紫・完了後が青です。過去の見出しも折りたためます。元の追加日時が不明なら「日時未記録」とし、過去の実績や日時は新たに作りません。バックアップにも残るタスク情報から再表示できます。

### タスク待ちの関連付け

カードの「タスク待ちを設定」から、タスクの完了を待つ項目と、相手待ちの解除を待つ項目を選択できます。

- 小さいタスクは、同じやるべきことの中の別の小さいタスク、または同じ案件内の別のやるべきことを選択できます。自分自身や自分の親は選べません。
- やるべきことは、同じ案件内の別のやるべきことを選択できます。
- 「相手待ちの解除待ち」では、同じ案件内の大タスク全体・やるべきこと・小さいタスクの相手待ちを選べます。自分自身の相手待ちは候補から外します。タスク全体の完了を待つ場合と区別して保存します。
- 相手待ちの候補には、その対象の直近の相手待ちコメント本文を表示します。選択欄には日時・画像・添付リンクを追加しません。本文が未記録ならその旨を表示し、解除済みの関連先も保存された本文で確認できます。
- 相手待ちを関連付けた側は黄色になります。返信や編集で関連先の相手待ちを解除すると、そのタスク本体は未完了でも進行可能になります。返信を再び相手待ちにした場合は黄色のまま待ち、後から相手待ちを再開した場合も黄色に戻ります。設定済みの関連先は、解除後も設定画面に「解除済み」として残ります。
- 完了待ちと相手待ちの解除待ちは併用でき、すべての条件を満たすまで待ちます。関連付けの保存だけで、その項目自身の相手待ちを解除することはありません。
- 完了・解除を待つ条件が1件でも残っていれば黄色で表示し、完了操作を無効にします。すべての条件を満たすと、通常は紫色の進行可能に戻ります。期限超過や自身の相手待ちがある場合は、その状態の色になります。
- 循環する関連付けは保存できません。関連先が未完了のまま削除された場合は待ち状態を維持し、設定画面で削除された関連先を外せます。
- 関連付けはJSONバックアップにも保存されます。

### 画像・リンク

画像は本文のテキストボックスに直接貼り付けられます。入力欄内のプレビューで、送信前の画像を確認・削除できます。PNG・JPEG・GIF・WebP・AVIF形式、1枚10MBまで対応し、送信後はクリックで拡大できます。本文なしの添付だけの送信も可能です。

URLも本文に直接貼り付けられます。HTTP/HTTPS・`www.`で始まるURLは、貼り付けた時点で入力欄内に青字・下線付きのハイパーリンクとして表示します。ほかのアプリからコピーしたタイトル付きリンクも表示名とリンク先を保持します。本文の途中への挿入・選択部分の置換、貼り付けの取り消しにも対応します。貼り付け元のHTMLの余分なレイアウト改行は取り込まず、クリップボードのテキストにある改行・意図した空行を保持します。引用・結論・相手待ち一覧でも認識し、別タブで開きます。過去に添付した表示名付きリンクも、表示・編集・引用を引き続き利用できます。

編集中は添付を追加・削除でき、キャンセルすると保存前の内容を保持します。引用は添付の送信時点の内容をコピーするため、引用元を編集・削除しても添付・本文のハイパーリンクは引用内に残ります。画像は外部アップロードせずIndexedDBに保存し、JSONバックアップにも含めます。週報には画像名とリンクを含め、画像のバイナリデータは含めません。

### 記録・追加・編集

入力欄のショートカットは次のとおりです。進捗リストボード横の「キー操作」から画面上でも説明を確認できます。Enterだけで改行します。変換中には送信しません。

| キー | 送信する内容 |
| --- | --- |
| Ctrl+Enter | 現在のチェック内容で送信 |
| Alt+Enter | 相手待ち |
| Shift+Enter | ただのコメント |
| Ctrl+Shift+Enter | 小さいタスクの追加 |
| Ctrl+Alt+Enter | やるべきことの追加 |
| Ctrl+Shift+Alt+Enter | 前提メモ |

小さいタスクの追加は、親のやるべきことを選択してから使えます。削除した小さいタスクの未返信の待ちコメントは、親のやるべきことの待ちとして扱います。複数の待ちがあるときは、1件に返信しても他の待ちを解除しません。

- Ctrl+Enter または「送信」で記録します。通常のコメントと「相手待ち」は、開いている大タスク・やるべきこと・小さいタスクが対象です。引用返信と既存コメントの編集では、元の対象を保持します。編集中に別のカードを開いた場合も、編集欄に元の対象名を表示します。「結論」はコメントのまとめ表示への指定です。
- 「やるべきことの追加」は本文から新しいやるべきことを作ります。期限の空欄時は親タスクの期限を使います。「○○までに【タイトル】」という追加メッセージを残し、配下のトークを未完了のうちから束ねます。見出しは完了前が紫、完了後が青です。「履歴を展開」で小さいタスクを含むトークを確認できます。進捗設定などから追加した場合も記録します。
- 「小さいタスクの追加」は開いているやるべきことの中に追加します。小さいタスクを開いている場合は、その小さいタスクと同じ親の中に追加します。大タスク全体の画面では、先にやるべきことのカードを開いてください。やるべきことが分かるトークへの引用返信でも追加できます。小さいタスク自体の期限入力は不要です。最初の追加トークを1件残します。
- 引用返信中も次の作業を追加できます。相手待ちへの返信で「相手待ち」を付けなければ待ちを解除し、付ければ緑で継続します。元の待ちメッセージは返信済みとして青または非表示になり、元の小さいタスク・やるべきこと自体は自動完了にしません。追加する次の作業も未完了で作成します。この返信を結論にした場合は返信元の結論として扱います。返信の引用は保持します。
- 編集は元の投稿日時と引用を保持します。本文や結論の指定だけの編集で、後から変更された状態を戻しません。
- トークの削除はほかのトークや保存済みの引用を消しません。未完了の小さいタスクの追加トークを手動で削除した場合は、その小さいタスクも削除します。追加トーク自体が完了記録になっている場合は、そのトークを削除してもカードは残し、未完了へ戻します。手動で削除した追加メッセージは自動復元しません。カードのごみ箱からの削除でも、過去のトークと引用は残します。
- 設定から名前・期限・やるべきことを変更できます。期限変更で理由を入力した場合だけ、変更日時・変更前後の日付・理由を記録します。不要な過去の自動ログは表示せず、保存済みデータは保持します。

進捗情報は既存の IndexedDB のタスク内に保存され、JSON のエクスポート・インポートにも含まれます。

トーク表示に失敗してもボード全体は消さず、別のカードに切り替えられます。「エラーの詳細」から表示内容を確認でき、保存済みデータは変更しません。過去データの画像・リンク欄がnullなどの場合も、添付なしとして表示します。

## 週報用レポート

標準出力はWord（.docx）です。添付画像・成果画像を文書内に埋め込み、リンクはクリックできる形でURLも残します。画像は該当コメント・引用の近くに配置します。ブラウザー内で実際のOOXML文書を生成するため、外部へのアップロードや追加サービスは不要です。GIFなどは静止画像として埋め込みます。出力形式の選択で従来のテキスト（.txt・画像名のみ）も選べます。

インポート／エクスポートの隣の「レポート作成」から、対象タスクと開始日・終了日を選んでWordファイルをダウンロードできます。初期期間は7日前から今日まで（両日を含む）です。進捗管理中のタスクを初期選択し、検索・一括選択・解除で対象を変更できます。未完了タスクと、指定期間内に完了したタスクだけを選べます。期間外に完了したタスクは表示・出力しません。定期予定の未完了分は期間内の回を表示し、完了分は予定日ではなく完了日時で判定します。

レポートには Copilot 向けの週報作成指示、選択タスクの情報、やるべきこと・小さいタスク、期間内の進捗・完了・相手待ち・理由付き期限変更、引用を記載します。日付範囲はブラウザーの現地時刻で両日を含み、コメントの投稿日時で抽出します。現在の状態や日時のない結果メモ、期間外の引用は参考情報として分け、期間内の実績と混同しない形式にしています。Wordには画像を埋め込み、テキストには画像名だけを出力します。コメントを伴わない小さいタスク・やるべきことの完了も、保存された完了日時が対象期間内なら記載します。レポート作成によってタスクや履歴は変更しません。

完了操作でタスク全体の `completedAt` を保存し、完了を取り消すと解除します。完了状態のままメモや期限を変更しても完了日時は変わりません。過去の完了日時未記録タスクは期限日を完了日として扱い、その旨をレポートに記載します。完了日時・期限日の両方がないものだけを対象から除外します。完了日時はJSONバックアップにも保持されます。

## ブラウザー回帰テスト

リポジトリのルートで実行します。Python 3.9 以上、Playwright と Chromium が必要です。

```sh
python3 -m pip install playwright==1.62.0
# システムの chromium がない場合
python3 -m playwright install chromium
python3 scheduleapp/tests/test_progress.py
```

テストは固定バージョンの React・ReactDOM・Babel・lucide-react・Tailwind の公式配布物を `cdn.jsdelivr.net` から取得し、実際の JSX をブラウザーで実行します。npm の導入やアプリのビルドは不要です。各テストで IndexedDB を分離し、ボードとの同期、ドラッグ操作、トークの集約と通常表示、完了の編集・取り消し、相手待ちの表示設定、画像・URLの実際のクリップボード貼り付け、期限変更履歴、色分け、引用、永続化とバックアップ、キャンセル時の保護、低い画面とモバイル幅での送信操作を検証します。
