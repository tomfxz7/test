# スケジューリングアプリ

`schedule.jsx` は React と `lucide-react` を利用するアプリです。既存の React 実行環境に読み込んで使用します。

## 進捗ページ

- ボードの親タスクで「進捗ページに表示」をチェックすると、進捗ページの未着手ボードに表示されます。チェックを外してもタスクと履歴は残ります。再度チェックすると未着手に戻ります。
- 未着手の「＋」から追加したタスクも、カレンダーボードや一覧で共有されます。定期タスクを選択した場合は、その日付の予定だけを独立したタスクとして管理します。
- 未着手のカードを着手中へドラッグするか「着手する」を押すと、やるべきことの設定が開きます。既存の小タスクが読み込まれます。新しい項目は Enter で追加し、Ctrl+Enter で設定を確定できます。キャンセル時は変更しません。
- 着手中のカードをクリックすると、そのタスクの進捗記録が右側に表示されます。コメントは左右に分けず、一人用の記録として日時順に表示します。通常の進捗コメントは青、相手待ちは緑、小さいタスクのコメントは紫です。小さいタスクも相手待ちの場合は緑を優先します。コメントは Ctrl+Enter または「送信」で記録します。
- コメントの「返信」から引用付きのコメントを送信できます。引用は本文・日時・関連項目の送信時点の内容を保存します。通常の引用元はそのまま残り、相手待ちの引用元は返信の送信後に一覧から削除して、新しいコメントの引用内に残します。その返信は小さいタスクのものでも青色になり、相手待ちを改めてチェックした場合は緑色になります。送信前のキャンセルでは引用元は変わりません。返信の編集でも引用は保持されます。引用中はタスク追加のチェックを使わず、コメントとして送信します。
- 自分のコメントの「編集」から、本文・関連するやるべきこと・相手待ち・完了・やるべきことの追加・期限を変更できます。「編集を保存」または Ctrl+Enter で確定し、「編集をキャンセル」または Escape で取り消します。編集したコメントには「編集済み」と表示され、元の送信日時は保持されます。本文だけの編集で、後から更新されたタスクの状態を戻すことはありません。
- 各記録の「削除」でコメントや期限変更理由の記録を削除できます。通常のコメント削除ではタスク・期限・完了／相手待ちの状態は変更しません。ただし、小さいタスクの追加コメントを削除した場合は、ひも付く小さいタスクも一緒に削除します。ほかのコメントや保存済みの引用は残ります。編集中や返信中の対象コメントを削除した場合は、その入力モードを終了します。
- 関連するやるべきことをチェックしてコメントすると、対象との関連が履歴に残ります。「完了」は関連項目を選んだときに利用できます。
- 「相手待ち」は関連項目の選択があればその小タスクだけに、なければ親タスク全体に反映します。チェックせずにコメントすると、対象の相手待ちを解除します。小タスクの完了で親タスク全体を自動完了にはしません。
- 「やるべきことの追加」をチェックして送信すると、コメント本文が新しい小タスクになります。追加操作のコメントや変更履歴は残しません。期限を空欄にすると親タスクの期限を使います。コメントの編集から追加に変更した場合も同じ扱いになります。
- やるべきことの下に、さらに期限なしの「小さいタスク」を追加できます。コメント欄の「関連するやるべきこと」を一つ選び、「小さいタスクの追加」をチェックして送信すると、本文がその項目になります。小さいタスクには期限を入力しません。追加した項目にひも付くコメントを1件残し、通常は紫色、相手待ちで追加した場合は黄緑色にします。追加コメントの編集でも項目は重複して追加されず、相手待ちのチェックを変更すると項目の状態とコメントの色が更新されます。
- カード内のやるべきことをクリックすると、小さいタスクの一覧を展開・折りたたみできます。小さいタスクをダブルクリックするか、Enter または「コメント」ボタンを押すと、その項目を対象にしたコメントを記録できます。一覧のごみ箱ボタンから小さいタスク自体を削除することもできます。その場合も過去のコメントや引用は履歴として残ります。
- 関連するやるべきことの選択と履歴の絞り込みは、やるべきこと単位で行います。小さいタスクのコメントも、親のやるべきことを選ぶと一緒に表示されます。
- カードの設定からタスク名・親タスクの期限・小タスクを編集できます。変更はカレンダーや一覧にも反映されます。期限を変更し、変更理由を入力した場合だけ、変更日時・変更前後の日付・理由を白色の記録として残します。理由のない期限変更や、追加・設定・名前・状態の変更では自動の記録を残しません。過去の不要な自動履歴も画面には表示しませんが、保存済みデータは保持します。
- 通常は青、相手待ちは緑、期限を過ぎると赤、完了は灰色です。期限超過を相手待ちより優先し、親タスクと小タスクは別々に判定します。
- 履歴はキーワード検索と小タスクによる絞り込みを併用できます。削除した小タスクの過去の履歴も残ります。

進捗情報は既存の IndexedDB のタスク内に保存され、JSON のエクスポート・インポートにも含まれます。古いデータは進捗対象の指定がない状態で読み込まれます。

## ブラウザー回帰テスト

リポジトリのルートで実行します。Python 3.9 以上、Playwright と Chromium が必要です。

```sh
python3 -m pip install playwright==1.62.0
# システムの chromium がない場合
python3 -m playwright install chromium
python3 scheduleapp/tests/test_progress.py
```

テストは固定バージョンの React・ReactDOM・Babel・lucide-react・Tailwind の公式配布物を `cdn.jsdelivr.net` から取得し、実際の JSX をブラウザーで実行します。npm の導入やアプリのビルドは不要です。各テストで IndexedDB を分離し、ボードとの同期、ドラッグ操作、コメント・状態・期限変更履歴、不要な自動コメントの抑制、期限変更理由の記録、コメントの色分け、引用返信と相手待ちコメントの置換、コメント編集とチェック項目の更新、永続化とエクスポート、キャンセル時の保護、低い画面とモバイル幅での送信操作を検証します。
